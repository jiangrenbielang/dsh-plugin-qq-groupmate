## 一、机器人完全不回复（最高频）

### 1.1 新装好之后机器人不理任何人
- **现象**：群友发消息机器人完全没反应，控制台也不产生会话。
- **原因**：出厂配置**白名单全空**（`allow.groups`/`allow.private` 都空，且 `allowAllWhenEmpty` 默认 false）——白名单外的会话**消息直接丢弃不记录**，不是"机器人坏了"。这是"不理我"最常见的原因。
- **解决**：设置页「白名单」勾选目标群/好友，或勾选"允许所有会话"（`allowAllWhenEmpty`）。

### 1.2 设置了白名单还是不回复
- **排查顺序**（设置页顶部有"体检卡"，四项全绿才算就绪）：
  1. **接口地址（Base URL）**：必填，OpenAI 兼容地址如 `https://api.deepseek.com/v1`；
  2. **模型**：填好地址后点「获取列表」或手动填模型 id；
  3. **白名单**：见 1.1；
  4. **OneBot 连接**：左上角状态点 🟢 = 已连上；🔴 = SnowLuma 没在跑或端口不对。
- **注意**：模型没配时消息会保留为未读，配好后下一条消息或手动"唤醒一次处理"会自动补处理积压——**不是丢消息**。

### 1.3 配好了却"时灵时不灵"
- **原因**：响应档位滑条太低。滑条四档：1 档只回被 @；2 档 +命中关键词；3 档按概率随机回（滑条 55 位置 ≈ 50% 概率）；4 档全回。**任何档位下被 @ 一定回**。
- **解决**：想要"每条都回"就把滑条拉到 4 档；3 档时"有时候回"是预期行为。关键词在「聊天设置 → 关键词」里填（默认空表 = 永不命中）。

### 1.4 私聊找它不理我
- **原因**：**私聊永远跟随全局档位**——档位 1（仅艾特）时私聊普通消息不响应。
- **解决**：私聊场景把滑条拉到 4 档（或 3 档高位）。

## 二、登录与连接（SnowLuma / OneBot）

### 2.1 怎么扫码登录 QQ
- **流程**：设置 → OneBot 勾选「QQ Agent 启动时自动拉起 SnowLuma」→「SnowLuma」页签点启动/打开 WebUI（端口 5099）→ **首次打开 WebUI 必须自己设一个密码**（出厂强制改密）→ 扫码登录 → 保持运行（最小化即可）。
- **提示**：「已启动，首次 QQ 登录需要几秒到几十秒」，等日志出现 listening。

### 2.2 状态点红色 / 顶部横幅"OneBot（SnowLuma）还没连上"
- **排查**：SnowLuma 是否在跑（SnowLuma 页签看日志）；设置里 WS 地址（默认 `ws://127.0.0.1:3001`）和 HTTP 地址（默认 `http://127.0.0.1:3000`）是否对；**改 OneBot 地址后要重启应用才生效**。
- **坑**：HTTP 栏误填成 WS 的 3001 端口会报 `HTTP 426`（报错自带提示"httpUrl 可能指向了 WebSocket 端口"）。

### 2.3 端口被占了 / 和别的机器人冲突
- **端口清单**：OneBot WS 3001（收事件）、HTTP 3000（发消息）、SnowLuma WebUI 5099、控制台 3210。
- **坑**：启动检查只探 WS 端口 3001——**如果机器上已有别的协议端（NapCat/LLBot 等都默认 3001）占着端口，QQ Agent 会误判"SnowLuma 已在运行"跳过启动**，然后连到别人的程序，出现"连上了但不回消息"。别同时跑两个 QQ 机器人协议端。
- **解决**：`netstat -ano | findstr :3001` 看谁占着；用别的协议端就把它配到别的端口，设置页改 WS/HTTP 地址；OneBot 令牌留空让程序自动从 SnowLuma 配置同步。

### 2.4 双重回复（同样的话回两遍）
- **原因**：开了两个 QQ Agent 实例，双份连 SnowLuma（有单实例锁防这个，但强行多开可能绕开）。
- **解决**：任务管理器确认只有一个 QQ Agent 进程；重启应用。

## 三、API / 模型配置

### 3.1 一直报 401（密钥错）
- **排查**：
  1. **Key 是掩码 `******` 没替换**——输入框初始就显示 `******`，以为填了实际保存的是旧 Key；
  2. **选中的提供商和 Key 不匹配**——Key 按提供商分开存（`dshProviderKeys`），"选了 openrouter 却拿着别的站的 Key"→ 全部 401；
  3. 切换过 SnowLuma 账号后 token 变了。
- **解决**：在「模型 API」里用「显示」确认当前真 Key、或重新输入新 Key；切换提供商后确认该提供商 hasKey 为真（用「测试全部提供商」批量验证）。

### 3.2 报 404 / 模型名错误
- **原因**：模型名不存在（API 返回 404/400）。**4xx 错误不会自动重试**（"重试也不会变好，只会白烧额度"），会话直接标 error。
- **解决**：设置页点「获取列表」拉取真实模型 id（注意大小写），或手动核对；用「测试连通性」发一次最小请求验证。

### 3.3 "获取模型列表"失败
- **常见**：Base URL 为空（提示"请先填写 Base URL"）；15 秒超时；401/403 = Key 没填或填了掩码；**404 = 端点可达但中转站没实现 /models 路由**——这种可以跳过列表，手动填模型 id。
- **解决**：填对 Key 再拉；没 /models 的路由就手动加模型。

### 3.4 机器人半天才回 / 显示"出错重试 1/2"
- **原因**：单次请求超时 180 秒，网络失败/超时/5xx/429 会自动重试 2 次（退避 1s/2s）。这是**正常机制**不是卡死。
- **注意**：**已经发过消息的会话不会重试**（宁可标 error 也不让群里看到两遍同样的话）——群里偶尔见"出错后没下文"是防重设计。

## 四、发消息相关

### 4.1 机器人突然不说话了 / 说"发送频率超限"
- **原因**：限频保护（默认每分钟最多 80 条、每小时 500 条），超限会报"发送频率超限（每分钟最多 80 条），请等一会再发"并告诉模型。
- **解决**：等 1 分钟/1 小时自动恢复；或设置里调高频次上限。另：模型发消息之间有人工节奏间隔（1~3 秒 + 按字数加），是正常现象。

### 4.2 超长消息被切成好几条
- **原因**：QQ 单条消息有硬长度限制，超过 4000 字自动切分（优先在换行处切，处理 emoji 防乱码）。
- **解决**：正常兜底，不用管。

### 4.3 发消息被腾讯风控 / 失败
- **原因**：OneBot 发送失败（retcode 非 0）会报错回给模型；QQ 图床 URL（rkey）会过期，图片转存/取图过期会失败。
- **解决**：降低发言频率、别刷屏；图片类功能趁早用。

### 4.4 "看不到图" / 图片相关失败
- **原因**：① 模型不支持视觉输入（工具会被移除，模型如实说看不到）；② 图片 URL 过期（QQ 图床 rkey 全网过期无法补救）；③ 自建内网图床被安全拦截（SSRF 防护禁内网，除非开 `security.allowPrivateImageHosts`）。
- **解决**：用支持图片输入的模型（设置里 vision 开关 + 模型目录视觉徽标）；内网图床需开安全例外。

## 五、记忆与存储

### 5.1 记忆整理后印象"变少了" / "整理失败"
- **原因**：自动整理是**只减不增**——合并重复、删过时（模型返回条数变多视为幻觉直接放弃）；整理失败时保留原印象不破坏。默认条件：印象超 4 条或某成员超 5 条，且距上次整理超 6 小时。
- **解决**：设置页可手动触发整理；整理前会自动备份到 `data/memory/backups/`。

### 5.2 磁盘占用越来越大
- **原因**：`maxMessagesPerChat` 和 `keepSessionFiles` 默认都是 **0 = 不限制**——消息存档和会话记录文件无限增长（README 明说"无数量上限"）。
- **解决**：设置里给两个值设上限（如 2000 / 300）；分享/备份前跑 `scripts/sanitize-release.mjs` 脱敏（清 Key/白名单/聊天存档/会话记录/SnowLuma 登录态）。

### 5.3 数据都存在哪 / 换电脑怎么迁移
- **位置**：**安装目录旁的 `data/` 文件夹**（config.json、messages/、sessions/、memory/、stickers.json、telemetry.json），不在 %APPDATA%。覆盖安装不丢数据。
- **迁移注意**：直接拷 `data/` 即可。⚠️ 分享前**必须脱敏**（见 5.2），否则你的 API Key、白名单、聊天记录全带出去。

## 六、桌面端 / 控制台

### 6.1 关窗后机器人还在跑
- **原因**：关窗 = 最小化到托盘（默认开启），不是退出。真正退出走托盘菜单「退出」。
- **解决**：设置「桌面端」可关掉"关窗最小化到托盘"。

### 6.2 浏览器打不开控制台 / 端口变了
- **原因**：控制台默认 3210，被占用自动顺延 3211~3219（Electron 窗口不受影响，浏览器手输 3210 会连不上）。
- **解决**：headless 模式看启动日志打印的真实端口（"控制台已就绪：http://127.0.0.1:PORT"）。

### 6.3 网页/窗口白屏或黑屏
- **原因**：已强制修过两样——部分显卡驱动渲染黑屏（禁硬件加速）、系统代理劫持 127.0.0.1 白屏（强制直连代理）。仍出现多半是环境问题。
- **解决**：重启应用；升级版本。

### 6.4 会收集我的数据吗（隐私）
- **QQ Agent 自身**：有匿名遥测（启动 90 秒后发一次、之后每 6 小时一次）——只含随机安装 ID + 版本号 + token 用量计数 + 工具名计数，**不含 QQ 号、群号、昵称、聊天内容、IP**；失败静默不影响使用。**没有 UI 开关**。
- **SnowLuma**：遥测默认开可关（环境变量 `SNOWLUMA_TELEMETRY=0` 或 WebUI 开关）；数据（QQ 凭据/关系/消息缓存）都在本机；WebUI 口令是加盐哈希不存明文。当前公开版未含遥测代码。

### 6.5 版本更新
- **机制**：启动时 + 每小时查一次新版本（kondius.cn），发现新版弹浮窗，**只提示不自动安装**。8 秒超时、失败不打扰。
- **解决**：按提示去官网下载新版覆盖安装（数据在 data/ 不丢）。

## 七、其他

### 7.1 搜索失败（机器人说"错误：搜索失败"）
- **原因**：默认 Bing 网页解析免 Key，被反爬/网络问题会失败；换用 DeepSeek/智谱/博查/百度/秘塔需要各自填 Key（留空回退环境变量）。
- **解决**：默认设置即可；换服务需填 Key；可自定义搜索服务。

### 7.2 合并转发消息显示"payload is empty"
- **原因**：QQ 的合并转发 `res_id` 会过期，展开失败。
- **解决**：模型有 `read_forward` 工具可重试，展开结果写回存档永久生效；过期太久的转发确实打不开。

### 7.3 机器人没按我改的档位/关键词工作
- **原因**：滑条位置是"唯一真相"——直接改配置文件里的 `contextTier` 会被滑条位置覆盖。
- **解决**：档位和关键词都在设置页 UI 里改，别手改 config.json。

### 7.4 机器人被暂停了
- **现象**：顶栏横幅"⏸ 机器人已暂停，不会处理任何消息。"
- **解决**：点「恢复」；「恢复并全部标为已读」= 跳过积压消息。
